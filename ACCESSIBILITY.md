# Accessibility

## Scope and current status

The Flutter web interface should support keyboard interaction, visible focus, meaningful control labels, readable validation messages, and usable layouts across screen sizes and appearance modes. These are contribution goals, not a claim that every screen currently meets them.

There is no documented comprehensive accessibility audit or verified WCAG conformance assessment for this repository. Known barriers are tracked through issues; the absence of an issue is not evidence that a flow is accessible.

## Report a barrier

Open a bug report here for web interface barriers. Include the affected screen or task, expected and actual behavior, browser and version, and assistive technology or input method if relevant. Screenshots or recordings are optional; a text description is sufficient. Report Keycloak login theme barriers in [Meterya API](https://github.com/roman-kiefer/meterya-api/issues/new/choose).

Use the [bug report form](https://github.com/roman-kiefer/meterya-app/issues/new?template=bug_report.yml). If the form itself prevents reporting, open a [blank issue](https://github.com/roman-kiefer/meterya-app/issues/new). No personal medical information is needed. Remove private data from attachments.

## Contributing improvements

Include accessibility considerations when changing controls, navigation, error feedback, or documentation. Describe the affected task and the keyboard or assistive-technology checks actually performed. See [CONTRIBUTING.md](CONTRIBUTING.md) for the contribution process.
